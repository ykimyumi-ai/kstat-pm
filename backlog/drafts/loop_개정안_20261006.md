# loop.md — 폐쇄형 학습 루프 운영 규약

> 이 워크스페이스가 매 세션 **누적 성장**하게 만드는 절차. 헤르메스 "closed learning loop"의 Cowork 구현.
> 규칙(행동·검증)은 `BRCORE/BRCORE운영/00_운영지침_MASTER.md`가 캐논. 본 문서는 **루프 절차**만 정의한다.
> 개정 2026-10-06(매니저 승인 대기): 교훈 적재처를 `_AGENT/lessons.md`에서 **피드백 백로그 단일 원장** `G:\내 드라이브\_피드백백로그\BACKLOG.md`로 일원화. 직전본 `loop_backup_2026-10-06.md`.

## 루프 도식

```
   ┌─────────────────────────────────────────────────────────┐
   │  ① 세션 시작: 회상 (USER·MEMORY·핸드오프 읽기)              │
   │            ↓                                             │
   │  ② 작업 중: 포착 (백로그·memory·skills_backlog 즉시 적재)  │
   │            ↓                                             │
   │  ③ 세션 종료: 정착 (핸드오프 갱신·적재 마감)                │
   │            ↓                                             │
   │  ④ 매주(자동): 넛지 (누락 점검·자산화·노후 정리) → review/  │
   └────────────────────────────┐  피드백  ┌────────────────────┘
                                 └──────────┘
```

핵심: **포착 없이는 성장 없다.** 작업 중 알게 된 것을 그 자리에서 적지 않으면 다음 세션은 같은 곳에서 다시 막힌다.

## [세션 시작 루틴] — 회상 (작업 착수 전)

```
□ 0. 팀프로파일(전역 자동 로드) §0 대로 — 브리핑·진도 대장을 읽고 이 요청의 과업·공정·담당을 판정한 뒤, 상황·권고·판단 대기 항목을 첫 보고에 올리고 지시를 기다린다 (2026-09-10 매니저 확정)
□ 1. _AGENT/USER.md 읽기 — 누구를 위해, 어떤 문체·원칙으로 일하는가
□ 2. _AGENT/MEMORY.md 훑기 — 적용될 사실·절대규칙·함정이 있는가
□ 3. 작업 대상 프로젝트의 최신 핸드오프 읽기 (handoffs/INDEX.md로 위치 확인)
□ 4. 피드백 백로그 — `G:\내 드라이브\_피드백백로그\inbox\`에 미병합 파일이 있으면 먼저 BACKLOG.md에 병합(_merged로 이동)하고, BACKLOG.md에서 이번 작업 도메인·`공통` 항목을 골라 첫 보고에 「백로그 대조: FB-xx 해당/해당 없음」 1줄을 적는다
□ 5. (파일 산출물·분석 과제일 때만) 운영지침_MASTER 1-1 '4대 질문' + 1-2 'MECE 계획'
□ 6. (상위 `E:\클로드작업` 연결 세션 한정) 신규 조사·통계·제안 프로젝트 폴더에 통계품질 KB 포인터 정비 — 규칙: `_AGENT/포인터정비_규칙.md`
```

> 단순 조회·조언·기계적 변환·오류 수정은 1~3만 빠르게 확인하고 바로 진행한다(4대 질문 생략).

## [세션 종료 루틴] — 정착 (대화를 닫기 전)

```
□ 1. 핸드오프 갱신 — 해당 프로젝트 HANDOFF의 '현재 상태'·'다음 작업'을 이번 세션 결과로 교체
     (신규 프로젝트면 handoffs/_TEMPLATE.md 복제). INDEX.md의 최신본 날짜 갱신.
□ 2. 교훈 적재 — 이번 세션에 막혔던/틀렸던 지점·매니저 지적을 BACKLOG.md §2에 기록했는지 확인 (지적은 받은 그 턴에 적는 것이 원칙, 여기서는 누락 확인만. 없으면 "없음" 명시)
□ 3. 메모리 적재 — 다음에도 쓸 '오래갈 사실'을 MEMORY.md(+ memory/ 파일)에 추가
□ 4. 스킬화 후보 — 이번에 2회+ 반복했거나 반복될 패턴을 skills_backlog.md에 등록
□ 5. 내장 메모리 동기화 — ①③의 핵심 1~2건을 Cowork 내장 메모리에도 반영(항상-로드 레이어)
```

> **완료 기준:** 위 5칸이 모두 체크(또는 "해당 없음" 명시)되면 종료. 미체크 항목이 있으면 닫지 않는다.

## [주간 점검 루틴] — 넛지 (매주 자동 실행)

스케줄러가 매주 월요일 이 루틴을 실행한다. 사람의 개입 없이 **루프가 새는 곳**을 찾아 메운다.

```
□ 1. 최근 1주 작업 폴더(프로젝트별 outputs·핸드오프 변경일) 훑기
□ 2. 미적재 점검 — 종료 루틴을 건너뛴 세션이 있는가? (핸드오프는 갱신됐는데 백로그/memory가 비었는가) + 백로그 inbox 미병합 파일 병합
□ 3. 스킬화 후보 점검 — skills_backlog 큐에서 '발생 3회+'에 도달한 항목 = 스킬 제작 권고로 승격. BACKLOG.md에서 재발 2회+인데 §1 승격 후보에 없는 항목을 올린다
□ 4. 노후 정리 — 90일 이상 손대지 않은 핸드오프·해소된 교훈을 '보관' 표시
□ 4-1. 팀프로파일 대조 — `01_context/연구8부_팀프로파일.md` §1~§5를 진도 대장·핸드오프·오류 대장과 대조해 낡은 줄을 찾고, 개정안을 review/ 보고서에 「프로파일 개정 제안」 절로 남긴다. 반영은 매니저 승인 후 (게이트⑤)
□ 5. 요약 보고 — 위를 _AGENT/review/주간점검_YYYYMMDD.md로 저장 (표 1개 + Next Step)
```

> **승인 경계:** 주간 점검은 *읽기·요약·후보 등록*만 한다. 실제 스킬 제작·원본 수정·규칙 변경은 **승인 게이트**(운영지침_MASTER 2-1의 ①④⑤) 대상이므로 권고만 남기고 멈춘다.

## 포착 규칙 — 무엇을 어디에 적는가

| 포착 대상 | 어디에 | 형식 |
|---|---|---|
| 막힘·오류·함정·재발방지책·매니저 지적 | `G:\내 드라이브\_피드백백로그\BACKLOG.md` §2 (단일 원장) | ID·일자·도메인·유형·무엇이·원인·1줄 규칙·재발·상태·출처 |
| 오래갈 사실(규칙·경로·이해관계자·확정 결정) | `MEMORY.md` + `memory/` | 한 파일=한 사실, 프론트매터 |
| 2회+ 반복하는 절차·산출 패턴 | `skills_backlog.md` §1 | 패턴·발생횟수·예상 트리거 |
| 기존 스킬의 결함·개선점 | `skills_backlog.md` §2 | 스킬명·증상·개선안 |
| 다음 세션 연속성(현재상태·다음작업) | `handoffs/` | `_TEMPLATE.md` 구조 |

`lessons.md`는 백로그로 이관을 마친 뒤 읽기 전용 보관본으로 둔다(새로 적지 않는다).

**판단 기준 한 줄:** *"다음 세션의 나에게 도움이 될까?"* → 예면 적는다. *"두 번째로 하는 일인가?"* → 예면 스킬화 후보.
