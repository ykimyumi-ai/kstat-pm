# 피드백 백로그 — 설치 안내

원장 본체는 Google Drive `/_피드백백로그/BACKLOG.md` 한 곳에만 있다. 이 문서는 원장이 모든 환경에서 **자동으로 읽히도록** 연결하는 방법이다. 아래 1~3은 Claude가 대신할 수 없어 사용자가 직접 해야 한다.

| # | 연결 경로 | 적용 범위 | 담당 |
|---|---|---|---|
| 1 | 개인 지침에 조회 훅 추가 | claude.ai·모바일·클라우드·로컬 전부 | 사용자 |
| 2 | `feedback-backlog` 스킬 업로드 | 스킬이 켜진 모든 환경 | 사용자 |
| 3 | 로컬 `~/.claude/CLAUDE.md`에 훅 추가 + `error-log.md` 이관 | 로컬 Claude Code | 사용자 PC |
| 4 | `kstat-pm/CLAUDE.md` | 이 저장소 세션 | 설치됨 |

## 1. 개인 지침 (claude.ai → 설정 → 개인 지침)

`<learning_loop>` 블록 맨 앞에 아래 문단을 그대로 넣는다.

```
피드백 백로그: 모든 지적·수정사항의 단일 원장은 Google Drive `/_피드백백로그/BACKLOG.md`다. 실질 작업 착수 전 원장과 `inbox/`를 읽고 착수 보고 첫 줄에 "백로그 대조: FB-xx 해당/해당 없음"을 적는다. 사용자가 지적하면 수정과 같은 턴에 원장(직접 편집 가능 시) 또는 `inbox/FB_YYYYMMDD_HHMM_요지.md`(커넥터만 있을 시)에 기록한다. 재발 2회 이상은 승격 후보로 제안한다. 세부 절차는 feedback-backlog 스킬을 따른다.
```

개인 지침은 모든 환경에서 매 대화마다 읽힌다. 따라서 이 한 문단이 다른 연결 경로가 모두 빠진 환경에서도 원장을 찾게 만드는 최소 장치다.

## 2. 스킬 업로드

`backlog/feedback-backlog.zip`을 claude.ai → 설정 → 기능(Capabilities) → 스킬 → 업로드로 올린다. 압축 안에는 `feedback-backlog/SKILL.md` 하나가 들어 있다.

스킬은 사용자가 "틀렸다·다시·또 그랬네" 같은 지적을 하는 순간 트리거된다. 기록 단계가 빠지지 않게 하는 장치다.

## 3. 로컬 PC (Claude Code)

### 3-1. 전역 훅

`%USERPROFILE%\.claude\CLAUDE.md` 맨 위에 추가한다.

```
## 피드백 백로그 (최우선)
- 단일 원장: `G:\내 드라이브\_피드백백로그\BACKLOG.md`
- 착수 시: `inbox\`에 미병합 파일이 있으면 먼저 원장에 병합하고 `inbox\_merged\`로 옮긴 뒤, 원장을 읽고 "백로그 대조" 1줄을 적는다.
- 지적을 받으면 원장 §2에 바로 기록한다. `rules\error-log.md`에 적을 때도 원장에 함께 남긴다.
```

### 3-2. 기존 대장 이관

`%USERPROFILE%\.claude\rules\error-log.md`와 `E:\클로드작업\CLAUDE.md`의 대장은 Drive에 없어서 이번 초기 병합(25건)에서 빠졌다. 둘 중 하나로 처리한다.

- 파일을 `G:\내 드라이브\_피드백백로그\` 폴더에 복사한다. 그러면 다음 Claude 세션이 어느 환경에서든 읽어 병합한다.
- 또는 로컬 Claude Code에서 "error-log.md를 피드백 백로그에 병합해"라고 지시한다.

## 4. 동작 확인

설치 후 새 대화에서 아무 실질 작업이나 요청한다. 응답 첫 줄에 `백로그 대조:`가 나오면 조회 경로가 살아 있는 것이다. 이어서 일부러 하나를 지적해 본다. `백로그 등재:` 한 줄이 나오고 Drive `inbox/` 또는 원장에 기록이 생기면 기록 경로까지 살아 있는 것이다.
