# feedback-backlog

사용자의 지적이 세션과 환경을 넘어 이어지게 하는 스킬이다. 원장은 Google Drive 한 곳에만 있고, 모든 환경(claude.ai 채팅·모바일·클라우드 Claude Code·로컬 Claude Code·Cowork)이 같은 원장을 읽고 쓴다.

## 위치

| 대상 | Drive 경로 | ID |
|---|---|---|
| 원장 | `/_피드백백로그/BACKLOG.md` | `1yQaVPipUD966wASGiDwtcDjXlx6MrvYD` |
| inbox | `/_피드백백로그/inbox/` | `1xIoBwXcDByIbWvTf0XHS6rVG4QI309Xe` |
| 폴더 | `/_피드백백로그/` | `1ya9mPwHnhmqxKy5zeyMWC7_T7FVQGMjg` |

로컬 PC에서는 Google Drive 동기화 경로 `G:\내 드라이브\_피드백백로그\`로 직접 연다.

ID로 찾지 못하면 Drive에서 `title = 'BACKLOG.md'`로 검색해 `_피드백백로그` 폴더 안의 것을 쓴다. 원장을 찾지 못하면 작업을 멈추지 말고, 찾지 못했다는 사실을 착수 보고에 밝힌다.

## 1. 조회 — 실질 작업 착수 시

1. 원장 전체를 읽는다(Drive 커넥터 `read_file_content`, 또는 로컬 파일 읽기).
2. inbox 폴더의 파일 목록을 확인하고, `_merged`에 들어가지 않은 파일을 읽는다.
3. 이번 작업의 도메인 태그(`공통` `검증` `수치해석` `문서작성` `HWPX` `XLSX·차트` `데이터매칭` `API` `블로그` `파일관리` `소통`)에 맞는 항목과 `공통` 항목을 골라 작업 기준에 넣는다.
4. 착수 보고 첫 줄에 적는다: `백로그 대조: FB-03·FB-08 해당` 또는 `백로그 대조: 해당 없음`.
5. 산출물을 내기 전에 해당 항목의 1줄 규칙을 다시 대조한다. 대조 결과를 완료 보고에 한 줄로 남긴다.

## 2. 기록 — 지적을 받은 그 턴에

트리거: T1 사용자 지적 · T2 자기 발견 반복 결함 · T3 사용자가 톤·구조·서식을 직접 고침 · T4 한 세션에서 같은 오류 2회.

1. 먼저 원장에서 같은 유형의 기존 항목이 있는지 찾는다.
2. 환경에 따라 기록한다.
   - **파일을 직접 고칠 수 있는 환경**: 원장 §2 표에 행을 추가한다. 같은 유형이면 새 행 대신 해당 행의 `재발` +1, `출처` 추가. 머리말의 등재 건수·최종 병합일을 고친다.
   - **Drive 커넥터만 있는 환경**: 커넥터는 기존 파일 내용을 수정할 수 없다. inbox 폴더에 `FB_YYYYMMDD_HHMM_<요지>.md`를 새로 만든다(`create_file`, `contentMimeType: text/markdown`, `disableConversionToGoogleType: true`). 양식은 원장 §3.
3. 수정 작업과 같은 턴에 기록한다. 세션 끝으로 미루지 않는다.
4. 사용자에게는 한 줄로만 알린다: `백로그 등재: FB-26(신규)` 또는 `백로그 등재: FB-06 재발 3회째`.

## 3. 병합 — 파일을 직접 고칠 수 있는 환경에서 착수할 때

inbox에 미병합 파일이 있으면 원장에 병합하고, 병합한 파일은 `inbox/_merged/`로 옮긴다. 삭제하지 않는다.

## 4. 승격 — 재발 2회 이상

- `재발 ≥ 2`가 되면 상태를 `승격후보`로 바꾸고 원장 §1에 올린 뒤 사용자에게 승격을 제안한다.
- 승격은 규칙 변경이므로 사용자 승인 후에만 반영한다. 반영처는 개인 지침, 해당 스킬 SKILL.md, 로컬 rules·프로젝트 CLAUDE.md 중 하나다.
- 반영처는 사용자가 직접 바꿔야 하는 곳(개인 지침·설치된 스킬)일 수 있다. 그 경우 넣을 문안을 그대로 제시한다.

## 금지

- 원장 밖에 새 교훈 대장을 만들지 않는다. 프로젝트 CLAUDE.md 대장이나 `error-log.md`에 적더라도 원장에 함께 남긴다.
- 한 번의 예외적 지적을 곧바로 영구 규칙으로 만들지 않는다.
- 원장의 행을 지우지 않는다. 틀린 항목은 상태를 `폐기(사유)`로 바꾼다.
