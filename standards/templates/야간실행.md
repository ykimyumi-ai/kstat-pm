# 야간 무인 실행 키트 (v1.0)

자리를 비운 사이 로컬 Claude Code 한 세션이 승인된 범위 안에서 작업을 끝까지 돌리게 하는 절차다. 목적은 **결과는 같고 불필요한 작업은 없게** 하는 것이다. 2026-11-08 밤에 세션 4개가 사용자 입력 7~10건으로 한도의 40% 이상을 쓴 사건의 재발 방지책이며, 규칙 근거는 `skills/task-intake/SKILL.md` v1.4 「토큰 예산과 자율 진행 상한」이다.

## 1. 야간에 돌릴지 먼저 판정한다 (하나라도 아니오면 낮에 한다)

| # | 질문 | 아니오일 때 |
|---|---|---|
| 1 | 사람 결정이 남은 항목이 0건인가(핸드오프 「미해결」에 매니저 결정 대기가 없다) | 결정부터 받는다. 무인 실행은 결정을 만들지 못한다 |
| 2 | 입력 파일·판 번호·완료 기준이 확정돼 있는가 | 명세서부터 확정한다 |
| 3 | 사람이 직접 하면 1시간 넘게 걸리거나 같은 처리를 대량 반복하는가 | 낮에 바로 한다. 짧은 일을 밤에 세션째 열어 두면 대기 턴만 쌓인다 |
| 4 | 완료 여부를 기계(검사기·재계산·diff)로 판정할 수 있는가 | 판정이 사람 눈에 달렸으면 아침 검토를 완료 기준에 넣는다 |
| 5 | 이 작업에 관련 없는 훅·알림이 켜져 있지 않은가 | 설치 요청문 `로컬설치_요청문_토큰가드.txt`를 먼저 적용한다 |

## 2. 야간 실행 명세서 (복사해서 채운다. task-intake 작업 명세서에 붙인다)

```
[야간 실행 명세서] 과업명 · v1 · 일자
- 핸드오프: 읽을 파일 경로(가장 최신 1개)와 「다음 할 일」 중 이번에 할 번호
- 입력: 원자료·정본 경로와 판 번호 (읽기 전용)
- 산출물: 경로와 새 판 번호 (덮어쓰지 않음)
- 완료 기준: 기계로 판정되는 항목 (예: 전 칸 재계산 불일치 0, 검사기 종료 코드 0)
- 처리 경로: 직접(기본). 서브에이전트가 필요하면 조건 번호와 개수
- 토큰 예산: 최대 판 수 3 · 최대 서브에이전트 호출 3 · 컨텍스트 한도 30만 · 종료 시 핸드오프
- 감사: 최종본 1회. 중간은 고친 자리만. 프라이데이/이비 필요 여부와 면제 승인 근거
- 목표 충돌 규칙: 부딪칠 수 있는 기준과 우선순위 (예: 내검 통과 대 답한 칸 보존 -> 보존 우선)
- 금지: 외부 제출·발송, 원본 덮어쓰기·삭제, 규칙 문서·메모리 변경
- 결정 대기 처리: 사람 결정이 필요한 항목은 결정대기.md에 모으고 그 항목만 건너뛴다
```

## 3. 시작 프롬프트 (로컬 Claude Code에 붙여 넣는다. 「<>」만 채운다)

```
야간 무인 실행이다. 아래 명세서 범위 안에서만 끝까지 진행하고, 중간에 나를 기다리지 않는다.

[명세서] <위 2번 명세서를 채워 붙여 넣는다>

실행 규칙:
1. 핸드오프 <경로>의 「다음 할 일 <번호>」만 한다. 다른 항목은 건드리지 않는다.
2. 단일 루프로 직접 한다: 작성 -> 검사기 -> 수정. 기계로 판정되는 것은 모델이 다시 판정하지 않는다.
3. 서브에이전트는 명세서에 적은 개수만, 한 번에 병렬로 띄우고 전부 모인 뒤 한 번에 처리한다. 결과는 파일로 받고 대화에는 결론 한 줄과 경로만 남긴다.
4. 감사는 최종본에 1회만 한다. 중간판은 만들자마자 _이전판으로 옮긴다. 같은 지적이 2회 반복되거나 차단 건수가 2판 연속 줄지 않으면 멈추고 결정대기.md에 적는다.
5. 기다림: 오래 걸리는 외부 프로세스는 한 번 시작하고 완료 알림을 기다린다. 폴링하지 않고, 기다리는 동안 상태 보고 턴을 쓰지 않는다.
6. 훅·알림이 같은 말을 되풀이하면 한 줄만 기록하고 작업으로 돌아간다. 같은 해명을 반복하지 않는다.
7. 이미지는 축소하거나 필요한 부분만 잘라 읽고, 같은 이미지를 다시 읽지 않는다. PowerPoint COM 렌더는 한 번에 하나만 돌린다.
8. 컨텍스트가 30만에 닿으면 하던 단계를 마무리하고 핸드오프를 쓴 뒤 멈춘다. 판 수·서브에이전트 호출 수가 예산에 닿아도 똑같이 멈춘다.
9. 사람 결정이 필요해지면 질문을 결정대기.md에 모으고, 그 항목만 건너뛰어 가능한 작업을 계속한다. 가능한 작업이 없으면 멈춘다.
10. 외부 제출·발송, 원본 덮어쓰기·삭제, 규칙 문서·메모리 변경은 하지 않는다.

끝나면 반드시:
- 핸드오프를 Drive /_핸드오프/ 에 HANDOFF_<키>_<업무>_YYYYMMDD_HHMM.md 로 새로 쓴다.
- 아침보고.md 한 장을 작업 폴더에 쓴다: 결론 5줄 이내 / 산출물 경로와 판 번호 / 검증 증거(명령과 실제 출력) / 결정이 필요한 것 / 사용량 요약(판 수·서브에이전트 호출 수·압축 횟수·멈춘 이유).
- 확인하지 못한 것은 [미확인]으로 적는다. 완료 기준을 통과하지 못했으면 완료라고 쓰지 않는다.
```

## 4. 아침에 보는 순서

1. `아침보고.md`의 「멈춘 이유」: 완료 / 예산 도달 / 결정 대기 중 무엇인지.
2. `결정대기.md`: 낮에 정할 것.
3. 검증 증거의 실제 출력. 증거가 없으면 완료로 받지 않는다.
4. 사용량 요약이 예산 안인지. 초과했으면 다음 밤 예산을 줄이거나 작업을 나눈다.

## 5. 이 키트가 막지 못하는 것

- 훅 `token_guard.py`는 경고만 한다. 예산을 지키는 것은 위 규칙을 따르는 모델이다. 한 번이라도 예산을 넘기면 경고를 차단으로 바꾸는 것을 검토한다.
- 로컬 파일은 클라우드 세션에서 읽지 못한다. 실행은 반드시 로컬 Claude Code에서 한다.
