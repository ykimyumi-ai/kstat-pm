# 국가승인통계 제안서 작성 마스터

> **스킬 버전 v2.0 (2026-11-05) · 표준 PROPOSAL_STANDARD v2.0 연동**
> 우선순위: 제안요청서 원문 > PROPOSAL_STANDARD(매니저 확정 표준) > 이 스킬의 일반 지침.
> 이 스킬의 고정 목차·레이아웃 지침은 **정본 제안서가 없을 때의 대체 수단**이다. 정본이 있으면 정본을 복제해 구성과 내용만 바꾼다(아래 Step -1).

## ★ 정본 우선 원칙 (v2.0 신설 · 모든 단계에 우선)

1. **빈 쪽에서 시작하지 않는다.** 매니저가 작성한 최신 제안서(정본)를 복제해 구성과 내용만 바꾼다.
   - 정본 1: `발표자료_2026년도 벤처기업정밀실태조사.pptx` (`01_제안서/2026년/12_벤처기업정밀실태조사/03_제출/`, Drive ID `1hkeSlVV1WDn9oQZ_J5rCVDrT2IQCH6y5`)
   - 정본 2: `제안서_2026년 중소기업실태조사 실사 제안서(0514).pptx` (`01_제안서/2026년/08_중소기업실태조사/03_제출/`, Drive ID `1NM3KpixWA72ixvmgLHUTJyYQ9UBIzCe-`)
   - 정본 목록의 최신본은 Drive `/_피드백백로그/PROPOSAL_STANDARD.md` §0을 따른다.
2. **정본은 렌더로 본다.** 문면 추출로는 쪽 짜임(좌우 2단·◉ 불릿·빨강 굵은 핵심 어구·검은 둥근 띠 제목·빨강 번호 배지·연회색 블록·「(계속 →)」)이 보이지 않는다.
3. **종결은 전부 개조식**(명사형 또는 ~함·~음)으로 쓴다. 「~한다」·「~합니다」 서술형 금지. 근거는 항목 끝 괄호로 단다.
4. **낱말은 정본과 제안요청서에 있는 것만** 쓴다. 조어와 내부 체계 용어(공정·감사역·게이트 등)는 쓰지 않는다.
5. **과업의 핵심·우선순위는 스스로 정하지 않고 착수 질문으로 받는다.** 같은 쪽이 세 판을 넘기면 멈추고 묻는다.
6. 설비·실적 제원은 정본에서 그대로 옮긴다. 전회차 값을 쓰지 않는다.

## 스킬 개요

이 스킬은 국가승인통계를 수행하는 리서치 기업(케이스탯리서치)의 수석 컨설턴트가 나라장터 경쟁입찰에서 수주할 수 있도록, 제안서 작성 전 과정을 체계적으로 지원한다.

핵심 도메인: 산업실태조사, 중소기업실태조사, 벤처기업실태조사 등 산업규모 추정 승인통계 및 승인 준비 통계.

### 좋은 제안서·PT의 정의

제안서와 발표자료의 궁극 목적은 **평가위원의 점수 변화와 "수주"라는 행동 유도**다. 미려한 디자인·풍부한 정보량은 수단일 뿐, 최종 산출물(Output)이 평가위원의 판단을 움직이지 못하면 실패한 제안서다. 본 스킬은 투입 시간·노력이 아닌 **산출물 품질과 행동 유발력**을 기준으로 작동한다.

```
     E RFP 커버리지 / F 문체) MECE 전수 검토
  → 산출물: 종합 판정 1줄 + 지적표(6열) + 우선 보완 3~5개
  → ★ 치명·높음 등급 지적 잔존 시 "제출 가능" 보고 금지 ★
  → 사용자 최종 확인 후 완료
```

## 핵심 규칙

1. **단계별 승인 원칙**: 한 단계 완료 후 반드시 사용자 확인을 받고 다음 단계로 진행한다. 전체를 한꺼번에 출력하지 않는다.
2. **모듈 간 연결**: 선행 모듈의 산출물이 후행 모듈의 입력이 된다. M1 분석 없이 M2를 시작하거나, M3 핵심 차별화 한 줄 미도출 상태에서 M5를 생성하면 경고를 출력한다. 상세 연결 규칙은 `references/m6-checklist.md`의 M6-2 섹션 참조.
3. **결론 선행 서술**: 모든 기술 서술은 결론 → 근거 → 보충 순서로 전개한다.
4. **수치 기반 어필**: 추상적 주장 대신 구체적 수치를 먼저 제시한다.
5. **정책 언어 미러링**: RFP와 발주처 문서에서 사용한 용어를 제안서에 자연스럽게 반영한다.
6. **방법론 선택 근거 필수**: "왜 이 방법을 선택했는가"를 반드시 1문장 이상 포함한다. 단순 나열 금지.
7. **고정 목차 삭제 금지**: M8-2의 🔒 항목은 RFP에 명시되지 않아도 반드시 포함한다. 고정 항목 누락 시 경고를 출력한다.
8. **체계도 vs 조직도 구분**: 사업추진 절차·프로세스 흐름도는 Ⅰ장 7절에, 투입 인력 조직도·역할 분담은 Ⅴ장 2절에 배치한다.
9. **장표 유형 구분 원칙**: **DOCX 제안서 본문은 컨설팅형(근거 빼곡·논거 중첩)**으로 작성하고, **발표 PPT는 혼합형(표지·섹션 분리 슬라이드는 젠형, 방법론·실적 슬라이드는 컨설팅형)**으로 구성한다. 공공 발주처 PT 관행상 순수 젠형은 "근거 부족"으로 감점 요인이 되며, 순수 컨설팅형은 "전달력 부족"으로 감점 요인이 된다.
10. **SIT(Single Information at a Time) 원칙**: 한 슬라이드·한 페이지에는 **하나의 핵심 정보(Head Message)**만 담는다. 헤드 메시지는 본문 근거로 1:1 뒷받침되어야 하며, 한 장에 2개 이상의 논점을 섞지 않는다. 위반 시 Step 4 시각화 단계에서 경고를 출력한다.
11. **AI 작성 티 용어 금지 원칙** ★절대 위반 금지★: 평가위원이 "AI가 썼다"고 인지하는 즉시 신뢰도가 떨어진다. 본문·표 제목·도식 라벨·발표 스크립트 어디에도 다음 용어를 사용하지 않는다.
    - **영문 약어형 금지**: USP, ROI, OKR, MVP, TBD, ASAP, CSF
      · 통계 용어로 정착된 약어(CV, RR, CI, DQ, M/M, RACI, PDCA, FGI, AAPOR)는 예외
      · KPI는 정부 RFP 본문에서 직접 사용한 경우에 한해 미러링 허용
    - **그리스 문자 라벨 금지**: 알파/베타/감마/델타 단계, 알파/베타 버전 등
      · 통계 유의수준 표기 α, β는 학술적 표준이므로 예외
    - **컨설팅 외래어 금지**: 시너지, 레버리지, 페인 포인트, 밸류 프로포지션, 게임 체인저, 디스럽션, 온보딩, 얼라인, 싱크업, 디퍼런시에이터, 인사이트(1회 초과 사용 시)
    - **작위적 동사구 금지**: "솔루션을 제공하다", "최적화된 시너지를 창출하다", "엔드 투 엔드로 커버하다", "원스톱 솔루션", "토탈 솔루션"
    - 본문 생성 직전 자체 검열을 거쳐 위반 단어 발견 시 즉시 한국어로 대체.
    - 권장 한국어 매핑은 본 문서 말미 **부록 [A]** 참조.
    - 예외 단 한 가지: RFP 본문이 해당 약어를 직접 사용한 경우에 한해 그대로 미러링 (핵심 규칙 5 정책 언어 미러링 원칙 우선).
    - **예외(추가): 본사 도메인 정착 용어**는 내부 분석 프레임 명칭으로 일관 사용하므로 모듈·내부 문서에서 유지한다. 단, **제안서 본문(평가위원 노출면)에서는 한국어로 풀어 쓴다.**
      · 유지 대상 예시: Wow Factor(M1-3 매트릭스 영역명), Must-Win(과제 매트릭스 분류), DQ 6대 차원
      · 본문 노출 시 한국어 권장: Wow Factor → "결정적 차별화 영역", Must-Win → "필수 우위 과제"
12. **제출 전 적대적 최종검토 의무(M9)** ★신규·위반 금지★: 완성 제안서(v1 이상)를 발주처·나라장터로 내보내기 직전에는 반드시 부록 [B] M9를 실행한다.
    - 검토자 역할은 "작성자"가 아니라 **"이 제안서를 탈락시키려는 가장 적대적인 심사위원 + 내부 최종 교정자"**로 전환한다.
    - **지적 3종 세트 강제**: 모든 지적은 [페이지 · 근거 인용 · 수정안]을 갖춘다. 셋 중 하나라도 없는 지적은 출력하지 않는다.
    - **근거 없는 총평 금지**: "전반적으로 우수함" 류의 무근거 총평을 쓰지 않는다. 판정은 지적표 집계 결과로만 내린다.
    - 사용자가 지적한 오류 1건을 고칠 때는 **동일 유형 전수 스캔**을 함께 실행한다(개별 수정 금지).

13. **정본 복제 원칙(v2.0)** ★위반 금지★: 신규 제안서는 정본을 복제해 구성과 내용만 바꾼다. 상단 「정본 우선 원칙」과 PROPOSAL_STANDARD v2.0을 따른다. 이 스킬의 다른 레이아웃 지침과 충돌하면 정본이 우선한다.
14. **심사위원 독립 채점(v2.0)**: 제출·보고 전에 과업 성격에 맞춘 전문 영역 4인 이상의 독립 채점을 받고, 채점을 모아 스스로 고친 뒤 결과와 함께 제시한다(FB-164). 요구 대조는 A(전용 쪽·절)·B(표 행·칸)·C(한 줄·낱말)·D(없음) 등급으로 판정하고, 배점 큰 항목의 C·D는 「반영」으로 보고하지 않는다(FB-188).

1. **검색**: 본문 초안 작성 직후, A-1~A-4 표의 모든 금지 용어를 텍스트 검색으로 일괄 점검한다.

### A-6. 표준 용어 사전 — 다음 세션 일관성 확보용

본 사전은 "USP", "KPI" 등 금지 용어를 한국어로 치환하면서 정착된 표준 용어 목록이다. 모든 모듈·산출물에서 동일 의미는 동일 용어로 표기하여 평가위원에게 일관된 인상을 준다.

| 표준 용어 | 의미 | 사용 맥락 |
|---|---|---|
| **차별화 한 줄** | 제안서 전체를 관통하는 1문장 슬로건 (구 USP) | 모든 모듈 공통 |
| **본사 차별화 요소** | 본사가 보유한 구체적 강점·자산·특허 (구 USP의 분해 단위) | 회사 개요·인프라·시스템 장 |
| **차별화 한 줄 후보** | 선정 전 도출된 복수 후보 메시지 | M3-3 Step 2 |
| **차별화 한 줄 도출 절차** | M3-3 모듈명 (구 "USP 도출 프레임워크") | 워크플로 참조 |
| **본사 강점 항목** | 산출물 정의용 (구 "차별화 포인트") | 제안 전략 1-pager 구성 요소 |
| **핵심 차별화 한 줄** | "차별화 한 줄"의 강조 표기 | SKILL.md Step 2 산출물 명세 |
| **성과 지표** | 정량 평가 척도 (구 KPI) | RFP 본문 외 모든 사용 |
| **마지막 인상에 각인되는 효과** | 발표 클로징의 기억 강화 효과 (구 Recency Effect) | M5 발표 가이드 |
| **결정적 차별화 영역** | 본문 노출용 (구 Wow Factor) | 1장·기대효과 장 본문 |
| **필수 우위 과제** | 본문 노출용 (구 Must-Win) | 1장·전략 장 본문 |
| **적대적 최종검토** | 제출 직전 6차원 전수 검토 절차 (M9) | 부록 [B] |
| **지적 3종 세트** | [페이지 · 근거 인용 · 수정안] | M9 지적표 작성 규칙 |
| **방어불가 오류** | 심사 현장에서 해명이 불가능한 오류(오탈자·수치 모순·출처 부재) | M9 종합 판정 |

### A-7. 정합성 유지 원칙

1. **용어 변경 시 동시 갱신**: SKILL.md의 표준 용어를 변경할 경우 9개 모듈 전체를 일괄 검색하여 동시 갱신. 단편적 변경 금지.
2. **참조 명칭 일치**: SKILL.md가 모듈을 참조할 때 사용한 명칭은 해당 모듈 내부 헤딩과 정확히 일치해야 한다. (예: SKILL.md Step 2의 "차별화 한 줄 도출 절차" = M3-3 모듈명)
3. **모듈 추가 시 사전 등재**: 신규 표준 용어 도입 시 반드시 본 [A-6]에 등재한 뒤 다른 모듈에서 사용. 사전에 없는 용어는 일관성 위반으로 간주.

## 부록 [B] M9 — 제출 전 적대적 최종검토 (Red Team Final Review)

완성 제안서를 제출 직전에 "떨어뜨리려는 눈"으로 전수 검토하는 모듈이다. 작성 지원이 아니라 **파괴 시도**가 목적이며, 파괴되지 않은 제안서만 제출한다.

### B-0. 역할·상황·목표·방법 (고정 — 검토 착수 시 그대로 선언)

| 구분 | 내용 |
|---|---|
| 역할 | 나라장터 기술평가에서 이 제안서를 **탈락시키려는 가장 적대적인 심사위원** + **내부 최종 교정자** 겸직 |
| 상황 | 제출 예정 제안서 v1(PDF/PPTX/DOCX). 제출 전 마지막 검토 (제출 마감일·시각을 명시) |
| 목표 | ① 방어불가 오류(오탈자·수치 모순) 0 확인 ② 확정 특장점 반영 확인 ③ "압도적으로 이기는가" 판정 + 보완점 제시 |
| 방법 | B-2의 6개 차원을 MECE 전수 검토. 모든 지적은 **[페이지 · 근거 인용 · 수정안] 3종 세트** |

### B-1. 입력 — 대조 기준 세트

검토는 반드시 **대조 자료**를 놓고 수행한다. 기억·추론으로 대조하지 않는다.

| 슬롯 | 내용 | 필수 여부 |
|---|---|---|
| 검토 대상 | 제안서 v1 파일 (PDF/PPTX/DOCX) | 필수 |
| 기준 ① | RFP(제안요청서) 원문 | 필수 |
| 기준 ② | 확정 특장점 문서(제안 특장점 1~2페이지) | 필수 |
| 기준 ③ | 제안서 통합본 직전 버전(버전 대조용) | 권장 |
| 기준 ④ | 인용 원천 데이터 — 공표 통계·공식 DB 실측치(통계명·연도·표 번호 특정) | 수치 인용 시 필수 |
| 기준 ⑤ | 투입 인력 이력·자문 교수 이력 원본 | 인력 서술 존재 시 필수 |
| 기준 ⑥ | 본사 실적 원장(ERP 등) | 실적 서술 존재 시 필수 |
| 기준 ⑦ | 외부 인용 시장수치의 정합 기준 문서(조사 명칭·연도·집계 범위) | 시장 규모 인용 시 필수 |

**미확보 자료 처리 규칙**
- 대조 자료가 없으면 해당 항목은 "대조 불가(자료 미확보)"로 표기한다. 추정으로 판정하지 않는다.
- 대조 불가 상태로 남은 외부 수치는 **본문에서 제외**를 기본 권고로 한다(제안서 수치 기재 프로토콜 5항과 동일).

### B-2. 검토 6차원 (MECE 전수)

#### A. 오탈자·표기

| 점검 항목 | 판정 방법 |
|---|---|
| 깨진 문자·자소 분리·오타 (예: "통게", "P:art:ner"류 기호 삽입) | 텍스트 전량 추출 후 정규식·사전 대조 스캔 |
| 중복 문장·중복 헤더·중복 페이지 | 문장 단위 해시 중복 검출 |
| 띄어쓰기 오류 (예: "중소도 시"류 어절 분절) | 어절 분절 패턴 스캔 |
| **지표명 문서 전체 통일** (동일 개념이 두 이름으로 존재하는지) | 개념별 표기 후보 전수 수집 → 1개로 통일 권고 |
| 표·그림·섹션 번호 중복·누락·순서 역전 | 번호 시퀀스 추출 후 결번·중복 검사 |
| 장·절 제목과 목차의 불일치 | 목차 ↔ 본문 헤딩 1:1 대조 |

#### B. 수치 정합

| 점검 항목 | 판정 방법 |
|---|---|
| 외부 수치 전부 출처(문서명·연도·표 번호) 특정 가능 여부 | 인용 대장 대조. 특정 불가 시 지적(등급 최소 "높음") |
| 표 내부 산술 (행 합·열 합 = 총계, 비율 합 = 100%) | 표 전수 재계산 |
| 인용 시장수치의 **집계 범위(스코프) 모순** | 동일 문서 내 서로 다른 범위 수치가 같은 지표로 병기되는지 검사 |
| 공표 데이터 기반 목표치가 **실측치를 상회**하는지, 산출 방식이 일관되는지 | 실측 시계열 ↔ 목표 시계열 대조, 증가율 산식 일관성 검사 |
| **예시 수치 삽입 금지** (근거 없는 %·점수) | `[0-9]+\.[0-9]+%`, `[0-9]+\.[0-9]+점` 등 유형별 정규식 전수 스캔 |
| 동일 수치가 문서 내 여러 곳에 등장할 때 전부 일치 | 수치별 등장 횟수 카운트 후 불일치 검출 |
| 서로 다른 조사·지역·연도·표본의 수치 결합 여부 | 한 문장 내 복수 출처 혼합 검사 (데이터 혼합 금지 원칙) |

#### C. 특장점 반영

| 점검 항목 | 판정 방법 |
|---|---|
| 확정 특장점 축이 본문에 **실제로 살아 있는가** (문구가 아니라 논거로) | 특장점 문서의 각 축 ↔ 본문 근거 페이지 1:1 매핑표 작성 |
| 축 ① "발주처 데이터를 아는 팀" 유형 — 인력·연구진·유사 수행 이력이 근거로 제시되는가 | 인력·실적 장과의 연결 확인 |
| 축 ② "설계에서 끝내지 않고 측정한다" 유형 — 검증·측정 체계와 수행 체계가 명시되는가 | 검증 장점 항목 수 ↔ 본문 서술 대조 |
| 인력·조직의 경쟁 우위가 **드러나는가**(나열이 아니라 우위로) | 경쟁사도 쓸 수 있는 문장인지 반문 |
| 검증의 "장점"이 명시되는가 — 쓸 수 있는 지표·방어되는 지표·목표가 서는 지표 | 해당 3개 효익의 본문 존재 여부 |

#### D. 적대적 승부 (핵심 논거 생존 검사)

- 제안서의 **핵심 승부 논거를 ★1~★n으로 사전 확정**한 뒤, 각 논거가 본문에 살아 있고 논리 붕괴가 없는지 검사한다.
- 표준 검사 항목:

| 점검 항목 | 판정 방법 |
|---|---|
| 각 핵심 논거가 본문 어느 페이지에서 **증명**되는가 | 논거 ↔ 페이지 매핑. 매핑 실패 = 논거 소실(등급 "높음" 이상) |
| 논거 간 상호 모순 여부 | 논거 쌍별 충돌 검사 |
| 지표 체계의 **독립성(MECE)** — 차원 중복·누락 | 지표 목록을 차원별로 분류하여 중복·결손 확인 |
| **순효과 보정** 논리 — 사업 효과와 외생 요인 분리 방법이 명시되는가 | 보정 방법 서술 존재 여부 |
| **통용성** — 표준 이식 vs 맞춤 설계의 입장이 문서 전체에서 일관되는가 | 상반 서술 검출 |
| 심사위원이 **문서 자체만으로 걸 수 있는 약점** | 적대적 재독 1회 — "이 문장을 반대로 읽으면?" |
| 경쟁사가 복제 불가능한 우위가 선명한가 | 회사명을 경쟁사로 바꿔 읽어도 성립하는 문장 = 차별화 실패로 지적 |

#### E. RFP 커버리지

| 점검 항목 | 판정 방법 |
|---|---|
| 과업 범위 전 항목 반영 | RFP 과업 항목 ↔ 제안서 페이지 1:1 매핑표(누락 0 확인) |
| 요구 산출물(정량·정성 지표, 중간·최종보고서 등) 전 항목 명시 | 산출물 목록 대조 |
| 평가항목·배점표 전 항목 대응 | 평가항목 ↔ 대응 장·절 매핑 |
| RFP 지정 용어·명칭을 그대로 사용했는가 | 정책 언어 미러링 확인 |

#### F. 문체

| 점검 항목 | 판정 방법 |
|---|---|
| 개조식(명사 종결) 유지 | 서술형 종결 어미 잔존 스캔 |
| 비유어·신조어·AI투 표현 금지 | 부록 [A] 금지 용어 + 과장 수식어 스캔 |
| 존재하지 않는 용어를 만들어 쓰지 않았는가 | 신조어 후보 추출 → 출처 확인 불가 시 삭제 권고 |
| 역공 가능 표현 | "~에 불과하다", "~만이 할 수 있다", "어떤 수행사가 투입되더라도", "충분히 달성 가능한 과업" 등 전수 검색 |
| 경쟁사·기존 수행사 폄훼 뉘앙스 | "기존에는 ~하지 못했다" → "향후 ~를 보완할 수 있다"로 교체 권고 |

### B-3. 범위 제외 (억지 트집 금지)

- 일정·투입 M/M·품질관리·위험관리의 **세부 수준**은 검토 범위 밖(작성자 보완 영역).
  단, 특장점상 인력·조직 서술과 그 안의 **수치·오탈자**는 검토 대상.
- 디자인·색상·아이콘 마감 완성도는 검토 범위 밖.
- 범위 밖 항목을 지적표에 올리지 않는다. 지적 건수를 늘리기 위한 트집은 검토 신뢰도를 떨어뜨린다.

### B-4. 출력 형식 (고정)

**① 종합 판정 (1줄)**
- 형식: `방어불가 오류 [있음/없음] (치명 n건·높음 n건) / 압도적으로 이기는가: [예/아니오]`

**② 지적표**

| 차원 | 페이지 | 문제 | 근거(원문 인용) | 수정안 | 심각도 |
|---|---|---|---|---|---|
| A~F | p.n | 무엇이 잘못되었는가 | 원문 그대로 인용 | 교체할 문장·수치 | 치명/높음/중간/경미 |

**③ 우선 보완 3~5개** — "압도적" 도달을 위해 제출 전 반드시 처리할 항목만 선별. 각 항목에 예상 소요와 처리 순서를 붙인다.

### B-5. 심각도 정의 및 판정 규칙

| 등급 | 정의 | 처리 |
|---|---|---|
| 치명 | 심사 현장에서 해명 불가 — 수치 모순, 출처 부재 외부 수치, RFP 필수 과업 누락, 발주처명·사업명 오기 | 수정 전 제출 금지 |
| 높음 | 감점 직결 — 핵심 논거 소실, 지표명 불일치, 표 산술 오류, 특장점 축 미반영 | 제출 전 수정 |
| 중간 | 설득력 손실 — 근거 빈약, 경쟁사도 쓸 수 있는 문장, 역공 가능 표현 | 시간 허용 시 수정 |
| 경미 | 인상 저하 — 띄어쓰기, 번호 순서, 표기 흔들림 | 일괄 교정 |

**"압도적으로 이기는가" = 예** 판정 조건 (전부 충족 시에만)
1. 치명 0건 · 높음 0건
2. D차원 핵심 논거 전부가 본문에서 페이지로 증명됨
3. C차원 확정 특장점 축 전부 반영 확인
4. E차원 RFP 과업·산출물·평가항목 커버리지 100%
5. 회사명을 경쟁사로 치환해도 성립하는 "복제 가능 문장"이 핵심 차별화 서술에 없음

하나라도 미충족이면 **아니오**로 판정하고 사유를 지적표 행 번호로 지시한다.

### B-6. 검토 실행 절차 (2회 독립 실행)

1. **1회차 — 기계 검증**: 텍스트 전량 추출 → 유형별 정규식 스캔(A·B·F) → 표 산술 재계산 → 매핑표 작성(C·E).
2. **2회차 — 적대적 재독**: 추출 텍스트가 아니라 **최종 파일을 페이지 순서대로 재독**하며 D차원 논거 생존과 문맥 붕괴를 확인.
3. 1·2회차 결과를 합쳐 지적표를 구성한다. 1회 검증 후 즉시 "완료" 보고하지 않는다.
4. 수정 후에는 **파일 재추출 → 재스캔**으로 잔여 0건을 확인한다(수정 스크립트 출력만 신뢰하지 않는다 — XML 인코딩 차이로 치환이 실패할 수 있다).
5. 오류 발견 시 사과 문구로 시작하지 않는다. ① 동일 유형 전수 스캔 ② 원인 특정·같은 범주 재검증 ③ 수정 완료본 제출 순으로 실행한다.
