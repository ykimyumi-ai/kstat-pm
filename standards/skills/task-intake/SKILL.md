# 착수 문답 절차 (task-intake) v1.0

목적: **처음에 집요하게 한 번 묻고, 그 뒤로는 막힘없이 끝까지 간다.** 재작업 한 판은 착수 문답 수십 번보다 비싸다(원장 §0-1: 판 하나를 다시 돌리면 약 100만 토큰).

## 원칙 5개

1. **묻기 전에 찾는다.** 파일·Drive·전회차 폴더·스킬·표준에서 확인할 수 있는 것은 묻지 않고 「확인한 사실」로 제시한다(FB-53, FB-01).
2. **결과를 바꾸는 것만 묻는다.** 질문마다 「답에 따라 무엇이 달라지는가」를 속으로 확인하고, 달라지는 것이 없으면 뺀다.
3. **한 번에 모두 묻는다.** 질문을 쪼개 여러 턴에 걸쳐 묻지 않는다. 모든 질문에 추천 기본값을 달아 「나머지 기본값」 한 마디로 답할 수 있게 한다.
4. **이해를 문서로 확인받는다.** 답을 받으면 작업 명세서 1장을 내고 승인을 한 번 받는다. 승인 뒤에는 명세서가 기준이다.
5. **실행 중에는 멈추지 않는다.** 새 의문이 생기면 가정을 기록하고 진행한다. 멈추는 것은 비가역 작업, 과업의 핵심·프레임 변경, 명세서와 정면 충돌하는 사실이 나왔을 때뿐이다.

## 단계

### 1단계 · 자체 탐색 (질문 전, 사용자에게 보이지 않게)

- Drive `/_피드백백로그/ACTIVE_RULES.md`와 해당 도메인 표준(제안서는 `PROPOSAL_STANDARD.md`)을 읽는다. `BACKLOG.md` 전문은 읽지 않는다.
- 첨부 파일, 같은 과업 폴더, 전회차 폴더(`01_제안서/<연도>/` 등), 정본·템플릿을 찾는다.
- 큰 파일(10만 자 이상)은 대화에 올리지 않는다. 디스크에 저장하고 스크립트로 필요한 부분만 뽑는다.
- 여러 폴더를 훑어야 하면 탐색 전용 서브에이전트에 맡기고 결론만 받는다.

### 2단계 · 질문 배치 (한 번)

아래 형식으로 **한 메시지에** 낸다.

```
[확인한 사실] (찾아서 확정한 것 — 틀렸으면 지적만 해 주시면 됩니다)
- 기준 자산: …(경로) / 입력 자료: …(최신본 판단 근거) / 마감: …(출처)

[질문] 번호: 답 형식으로 답해 주시고, 생략한 번호는 추천값으로 진행합니다.
| # | 질문 | 추천값 | 이 답이 바꾸는 것 |
|---|---|---|---|
| 1 | … | … | … |
```

- 공통 질문 목록에서 1단계로 확정하지 못한 것만 고르고, 유형별 질문을 더한다.
- 질문은 보통 8~15개로 한다. 15개를 넘으면 결과를 덜 바꾸는 것부터 추천값으로 돌린다.
- 선택형으로 물을 수 있으면 선택지를 준다.

### 3단계 · 작업 명세서 (승인 1회)

```
[작업 명세서] 과업명 · v1 · 일자
- 목적: 받는 사람이 이 산출물로 할 다음 행동 1줄
- 산출물: 형식·분량·판형·파일명 규칙
- 기준 자산: 정본/템플릿/전회차 (경로)
- 입력: 원자료 경로와 판 번호
- 핵심과 우선순위: (사용자 답 그대로)
- 확정 사항(바꾸지 않음): 수치·문안·디자인
- 범위 밖: 하지 않을 것
- 완료 기준: 검증 항목과 통과 조건
- 기한: 외부 마감 / 내부 선행 기한 / 중간 보고 시점
- 처리 경로: 직접 또는 서브에이전트 N개 (사유)
- 가정: 추천값으로 정한 항목 목록
```

- 승인 신호(「진행」「OK」 등)를 받으면 실행한다. 수정 지시가 오면 명세서만 고쳐 다시 내지 않고 반영 즉시 실행한다.

### 4단계 · 무중단 실행

- 명세서 범위 안의 조사·작성·검증·수정은 묻지 않고 한다.
- 실행 중 생긴 의문은 「가정 대장」에 적고 합리적 기본값으로 진행한다.
- 같은 쪽이나 같은 산출물이 세 판을 넘기면 멈추고 원인을 보고한다(FB-185).

### 5단계 · 보고

- 첫 줄: `적용 표준: … · 백로그 대조: …`
- 결과, 완료 기준별 통과 여부, 가정 대장, 남은 한계만 적는다.
- 지적을 받으면 같은 턴에 inbox에 기록한다.

## 유형별 추가 질문

**제안서·발표자료**
- 제안요청서·과업지시서·평가표 경로, 정량·정성 배점
- 현 수행사와 예상 경쟁사, 우리가 이겨야 할 평가항목
- 내세울 실적 후보와 투입 인력·조직도 확정 여부
- 발표 여부·시간·발표자
- 회의 녹취나 발주처 면담 메모 유무(FB-187)
- 예산·기간 등 고정 제약

**통계표·결과보고서**
- 조사표 최종 판, 가중치 적용 여부와 가중 변수
- 공표 단위·표 서식 정본, 전년 비교 기준과 단절 여부
- 0건 `-`와 `0.0` 표기 규칙(FB-128), 그래프 형식(엑셀 네이티브 여부)

**데이터 검증·내검**
- 내검 규칙 정본 판, 조사표 분기(☞) 정본(FB-143)
- 쿼터·표본 배정표, 보정·대체 허용 범위
- 식별 정보 처리 방식(FB-52)

**조사표·문항 설계**
- 승인통계 여부와 문항 변경 허용 범위
- 조사 방법(면접·전화·웹), 응답 단위(사업체·기업)
- 전년 문항 유지 범위, 응답 부담 상한(문항 수·시간)

**개별 리포트**
- 템플릿 판, 대상 건수, 공표 전후 시점
- 포함할 정보와 금지 정보(통계법 비밀보호)

**분석·글**
- 데이터 출처와 단위, 독자, 결론 방향을 정해 둔 것이 있는지

## 토큰 운용 규칙

- **직접 처리:** 문자열 치환, 파일 하나 편집, 대체 문안이 이미 나온 수정(직접 약 2만 토큰 대 위임 약 25만 토큰 — 원장 §0-1).
- **서브에이전트:** 여러 폴더 탐색, 대량 웹 조사, 독립 검증(심사위원 채점), 긴 로그 분석. 결론과 근거 위치만 받는다.
- **감사 범위:** 중간 감사는 고친 자리만 본다. 전수 감사는 제출 직전 1회로 한다.
- **원장 조회:** `BACKLOG.md`는 FB 번호나 키워드로 해당 행만 뽑는다.
