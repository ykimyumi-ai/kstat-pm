# 2026 납품대금 연동제 실태조사 제안서 — 편집 가능 PPTX (발췌 13장)

원본 발췌본을 편집 가능한 PPTX로 재제작한 것이다.
1차로 PDF 11장(1~11장), 2차로 PNG 2장(12~13장)을 받아 처리했다.

## 왜 "변환"이 아니라 "재제작"인가

원본 PDF를 뜯어보면 자동 변환이 원천적으로 불가능하다.

| 검사 항목 | 결과 |
|---|---|
| 페이지 수 | 11 |
| 2차분 | PNG 2장(1536×1024) — 애초에 텍스트가 없는 이미지 |
| 텍스트 연산자(`Tj`/`TJ`) | **0건** — 텍스트 레이어가 없음 |
| 임베드 폰트 | 더미 `Helvetica` 1종(실제 미사용) |
| 페이지 구성 | 페이지당 이미지 XObject 1개 = 전면 래스터 이미지 |
| Producer | ReportLab (이미지를 PDF로 묶은 것) |

즉 원본은 "글자가 그려진 그림 11장"이다. PDF→PPTX 변환기를 돌리면 그림 11장이
붙은 PPT만 나온다. 그래서 모든 글자·도형·표를 네이티브 PPT 객체로 다시 그렸다.

## 산출물

```
out/2026_납품대금연동제_실태조사_제안서_발췌11p.pptx      # 1차 발췌 11장
out/2026_납품대금연동제_에너지경비_작동지표_2p.pptx        # 2차 발췌 2장
```

- **11.0 × 7.333 in**(원본 이미지 비율 3:2)
- 모든 텍스트가 편집 가능한 텍스트 박스 / 모든 도형이 네이티브 도형
- 10장 비목별 산출표는 `slide.addTable()` 네이티브 표 → 엑셀로 바로 붙여넣기 가능
- 폰트: `KoPub돋움체 Bold` / `KoPub돋움체 Medium` (kstat-ppt 표준)

## 다시 만들기

```bash
npm install
npm run build          # 11장 파일
npm run build:energy   # 에너지경비·작동지표 2장 파일
node build.js --only 3,10     # 특정 장만 (레이아웃 확인용)
```

수치나 문구가 바뀌면 **`content.js`만 고치면 된다.** 레이아웃 코드와 분리해 두었다.

## 검증

```bash
python3 verify.py out/…발췌11p.pptx --ids s01,s02,s03,s04,s05,s06,s07,s08,s09,s10,s11
python3 verify.py out/…작동지표_2p.pptx --ids s12,s13
bash tools/render.sh  # PPTX → PDF → 장별 PNG (눈으로 원본과 대조)
```

`verify.py`가 확인하는 것:

- 대상 슬라이드 수 / 규격 11.0×7.333in
- 슬라이드당 도형 20개 이상 (kstat-ppt 원칙 17 도형 밀도)
- 금지 요소 0건: `roundRect` 도형, `shadow`, 8자리 hex
- 폰트 크기 전량 10pt 이상 (kstat-ppt 원칙 15)
- 네이티브 표 존재(10장이 대상일 때)
- **`content.js`의 모든 문자열이 PPTX 안에 실제로 들어갔는지 전수 대조**

현재 상태: 두 파일 모두 전 항목 통과 / 원문 누락 0건.

## 구성

| 파일 | 역할 |
|---|---|
| `content.js` | 13장 전체 원문(문구·수치). **수정은 여기서** |
| `theme.js` | `namp-2026` 컬러·폰트 토큰, 픽셀→인치 환산기 |
| `helpers.js` | 공통 컴포넌트(pill·패널·배지·타임라인·불릿·대형숫자 등) |
| `fontmetrics.js` | KoPub TTF에서 글자 폭을 직접 읽어 넘침을 계산으로 차단 |
| `slides/s01~s13.js` | 장별 레이아웃 |
| `build.js` | 엔트리 |
| `verify.py` | 구조·원문 자동 검증 |
| `tools/measure.py` | 원본 PNG에서 도형·텍스트 좌표 실측 |
| `tools/crop.py` | 원본 일부를 확대 저장(작은 글자 판독용) |
| `tools/render.sh` | PPTX → PDF → PNG 렌더 |

## 설계 메모

**좌표는 눈대중이 아니라 실측이다.** 원본 이미지에서 색상 경계를 스캔해 도형의
픽셀 좌표를 뽑고(`tools/measure.py`), 그 값을 그대로 코드에 쓴 뒤 `theme.js`가
인치로 환산한다. 슬라이드 코드의 숫자는 전부 원본 픽셀 좌표다.

**글자 크기도 실측 기반이다.** 원본에서 잰 한글 잉크 높이(px)를 `s.FS()`가 pt로
바꾼다. 계수 0.99는 원본의 제목·부제·인용문·각주 4개 표본에 대해 KoPub 실제
메트릭으로 계산한 폭이 원본 폭의 0.98~1.04배가 되도록 맞춘 값이다.

**넘침은 계산으로 막는다.** `fontmetrics.js`가 KoPub TTF의 advance width를 직접
읽어 문자열 폭을 계산하고, 렌더러가 한글↔서양문자 경계에 넣는 약 0.25em 간격까지
반영한다. 이 값으로 폰트를 자동 축소해(최소 10pt) 박스를 벗어나지 않게 한다.

**pill(양끝 둥근 라벨)은 도형 합성이다.** kstat-ppt가 `ROUNDED_RECTANGLE`을
금지하므로(PPT 손상) 모서리 원 4개 + 사각형 2개로 합성했다.

## 원본과 다른 점 (의도된 차이)

1. **7·8·9·11장은 원본이 A4 가로 비율(1.414)**이다. 확정 규격인 3:2(1.5)로 옮기면
   세로 여유가 약 6% 줄어, 이 4장은 행 간격·패딩이 비례로 좁아졌다. 글자는 그대로다.
2. **원본의 초소형 주석은 10pt 미만**이지만 kstat-ppt 원칙 15(최소 10pt)에 따라
   10pt로 올렸다. 그래서 1장 우측 골드 배지, 2장 판별조사팀 주석 등 몇 곳은
   원본보다 배지가 넓거나 두 줄이 된다.
3. **3장 단계 카드**는 원본(357~628px)보다 7px 아래로 늘렸다. 원본 본문이 10pt
   미만이라 최소 10pt를 지키면서 같은 내용을 담으려면 그만큼 여유가 필요했다.
4. **10장 비목별 산출표**의 열 너비는 원본(197/500/175px)이 아니라 230/442/200px로
   다시 나눴다. KoPub이 원본 서체보다 넓어 비목명·금액이 접히는 것을 막기 위해서다.
5. 페이지마다 상단 라벨·번호 체계가 제각각인 것(4장 "8.", 10장 "2.", 11장 "5.")은
   **원본 그대로 유지**했다. 발췌본이라 원 덱의 번호 체계를 임의로 고치지 않았다.
6. **12장 ① 본문 첫 줄**(`원가구조를 재료비…4구분으로 기재`)은 10pt에서 494px가
   필요한데 원본 본문 열은 436px이라 두 줄이 된다. 열을 넓히면 옆의 `설계 근거`
   열이 밀려 더 큰 왜곡이 생겨, 두 줄을 택했다.
7. **13장 좌 패널**은 원본(18~926px)보다 18px 넓다. 10pt 하한에서 ③ 회피율·②
   이행률 산식이 각각 468·430px를 요구해 원본 폭으로는 산식이 두 줄로 접힌다.
8. **13장 하단 ② 공표 단위**는 원본 3줄이 4줄이 된다. 옆 열의 악센트 바와
   부딪히지 않는 선에서 최대로 넓힌 결과다.

## 원본 오탈자 교정 (2차, 사용자 승인)

원본을 4배 확대해 판독한 결과 명백한 오탈자 4건을 교정했다. 되돌리려면
`content.js`에서 해당 문자열만 원문으로 바꾸면 된다(각 항목의 `fixes` 필드에
원문을 남겨 두었다).

| 장 | 위치 | 원문 | 교정 |
|---|---|---|---|
| 12 | ① 에너지경비 비중 본문 | 재료비·노무비·**에너지정비**·기타 | 에너지**경**비 |
| 13 | ③ 회피율 기준·제외 | 쪼개기 **표함** | 쪼개기 **포함** |
| 13 | ④ 반영률 기준·제외 | **반영를** 산출에서 제외 | **반영률** 산출에서 제외 |
| 13 | ③ 기준시점·최소표본 | 병합표로 **인정 총 통합** | 병합표로 **인접 층 통합** |

마지막 1건은 5장의 같은 표현("미달 셀은 사전 확정 병합표에 따라 인접 층 통합")에
근거한 판단이다.

## 렌더 검증의 한계

`tools/render.sh`는 LibreOffice로 렌더한다. 컨테이너에 KoPub돋움체를 설치해 두면
실제 폰트로 검증되지만, LibreOffice와 PowerPoint는 자간·줄바꿈 규칙이 미세하게
다르다. 배치 어긋남·겹침·잘림은 이 검증으로 잡히며, 마지막 확인은 실제 PowerPoint에서
한 번 열어보는 것이 좋다.
